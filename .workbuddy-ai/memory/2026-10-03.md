# 2026-10-03

## 修复:切频道后文章列表"追加"而非刷新(重复 key 导致 DOM 残留)

**现象**:选中频道 A → 开「只看未读」→ 切到频道 B → 切回 A,列表不是替换刷新,而是 B 的文章留在上方、A 的文章追加在下方。

**根因链**(用真实后端 + agent-browser + fetch 延迟钩子 + 代码埋点定位):
1. `frontend/src/lib/api.ts` 的 `getArticles()` 拼接 URL 有 bug:by-feed / by-tag / by-category 的 path 已带 `?feed_id=x`,再拼 `'&' + qs(params)` 而 `qs()` 自带 `?` 前缀,结果变成
   `/api/articles/by-feed?feed_id=20&?page=2&page_size=20`
   → `page` 变成参数名 `?page`,后端收不到,**永远返回第 1 页**。
2. 触底 `loadMore()` 因此每次都追加同一页 → `articles` 出现重复文章 → `key={article.id}` **重复 React key**。
3. 切回频道 A 时,旧列表是带重复 key 的 40 项,新列表是 20 项;React 列表协调在重复 key 下清理失效,**旧频道 DOM 节点残留**,新频道内容被"追加"到下方。
   - 关键证据:切换回 A 后 React state `articles.length=20`(全是 A),DOM 却有 40 行(B 20 + A 20)。

**修复**:`api.ts` 中先 `qs(params).replace(/^\?/, '')` 去掉前缀,再按 path 是否已有 `?` 决定用 `?`/`&`。仅 1 文件 3 行。

**验证**:同一时序(600ms 延迟 + 触底滚动)下,修复后 URL 为 `?feed_id=20&page=2`,page 2 返回不同文章,最终列表 40 行全为 A、dup=0;全部/分类视图翻页亦正常。

**测试注意**:
- 本地联调:`php think run --port 8000` + `frontend` 下 `vite`(3000,base `/static/app/`),登录可用任意用户名 + 密码 `ya6916480`(AuthController 里硬编码,`password_verify` 被注释掉)。
- 数据库原本所有文章 `read=1`(未读数为 0),验证「只看未读」需先把部分文章标记为未读;已还原。

**发现但未改动的隐患**:
- `view/index/index.html`(生产壳视图)引用的 `index-COrKiv6X.js / index-gIFLucD6.css` 在 `public/static/app/assets/` 中不存在,生产入口会 404;重新构建 + `scripts/sync-shell.mjs` 可修复。
- 重复 key 的隐患仍在:后端 offset 分页在刷新任务插入新文章时可能返回重叠数据。可考虑 append 时按 id 去重作为兜底。

## 追加:append 按 id 去重兜底(已实现)

`Reader.tsx` 的 `fetchPage` 追加分支改为先建 `Set(prev ids)` 再过滤 `data.list`,只追加新 id。重载分支不变。
- 验证:用 fetch 钩子把 `page=2` 改写成 `page=1` 伪造重叠页 → 触底后列表仍 20 条、dup=0(修复前会变成 40 条含 20 重复)。
- 恢复真实分页后触底仍正常追加(page=3/4,20→40→60,dup=0)。
- 注意:去重后若后端持续返回完全重叠页,`articles.length` 不再增长而 `total` 不变,理论上"没有更多文章了"不会出现;正常分页下不会触发。

## 追加:「追加 0 条新数据即视为到底」(已实现)

- `Reader.tsx` 新增 `endReached` state;`fetchPage` 重载时置 false,追加时若 `fresh.length === 0` 置 true 并保持列表不变(返回 `prev`,避免无谓重渲染)。
- 新增派生值 `hasMore = !endReached && articles.length < total`;`loadMore` 守卫与 ArticleList 底部状态都改用它。
- `ArticleList` 的 `total` prop 换成 `hasMore`(total 只被那两个底部条件用到,`count` 仍单独传真实总数)。
  - 特意没有把 `total` 收敛成 `articles.length`,否则列表头部的条数会从 961 变成 20,显示错误。
- 验证:伪造重叠页触底后 n=20、spinner 消失、"没有更多文章了"出现、头部仍显示 961;正常分页 20→40→60 不受影响;14 条的短频道天然到底也正确显示"没有更多文章了"。
- 已知语义:`endReached` 会保持到下一次重载(切频道/搜索/筛选),即后端恢复后同一视图内不会自动重试。
